# Module 03: Risk Heatmap Dashboard
## Key Deliverable Component (b) — Technical Specification

---

## 1. Overview & Operational Role

The **Risk Heatmap Dashboard** provides Law Enforcement Agencies (LEAs), State Police Control Rooms, and Bank Fraud Monitoring Desks with an intuitive, GIS-enabled spatial intelligence interface. It translates complex graph-neural and gradient-boosted probability vectors into real-time geographic risk representations.

---

## 2. GIS Architecture & Offline-First Design

### 2.1 Zero-Tile Vector Rendering
To comply with strict government intranet (e.g., CCTNS / POLNET / secure LEA perimeters) and field deployment requirements without internet connectivity:
- The dashboard **does not rely on external tile providers** (e.g., Google Maps, Mapbox, OpenStreetMap servers).
- Boundary polygons are served directly as GeoJSON from the backend API (`GET /districts`) and rendered natively using SVG / Canvas vectors via `react-leaflet`.
- ATMs are plotted using lightweight `CircleMarker` primitives with vector styling, avoiding external image assets that break in sandboxed environments.

### 2.2 Visual Encoding Hierarchy

| Visual Element | Representation | Operational Meaning |
|---|---|---|
| **District Polygons** | Semi-transparent vector boundaries with subtle stroke outlines | Administrative jurisdiction boundaries (e.g., Police District / Commissionerate). |
| **ATM Hotspot Markers** | Circular markers with proportional radiuses and dynamic color scale | Individual ATM / Cash Point risk score. |
| **Color Temperature** | Emerald ($P < 0.10$) $\rightarrow$ Amber ($0.10 \le P < 0.35$) $\rightarrow$ Crimson ($P \ge 0.35$) | Likelihood of imminent cash-out. |
| **Dashed Stroke Rings** | Concentric pulsing dashed vector strokes | **Predicted event** (distinguishing prospective ML forecasts from historical ground events). |
| **Selected ATM Halo** | High-contrast neon-accent bounding ring | Active inspection target showing detailed telemetry. |

## 3. Interactive Drill-Down & Filtering Mechanisms

### 3.1 Horizon & Threshold Selectors
1. **Forecast Horizon:**
   - `2 Hours:` Immediate rapid-response tactical window (for nearby PCR patrol dispatch).
   - `6 Hours:` Standard inter-agency coordination window (bank ATM cash replenishment & liaison).
   - `24 Hours:` Strategic daily patrol allocation and surveillance deployment.
2. **Probability Cutoff Slider:**
   - Adjustable threshold filter ($\tau \in [0.0, 1.0]$) to suppress low-confidence noise and isolate priority targets.
3. **Model Selector:**
   - Switch dynamically between **Graph-Aware XGBoost**, **Spatial KDE**, and **Recency Baseline** to compare model convergence and spatial distribution.

### 3.2 Inspector Side-Drawer
Clicking any ATM marker opens an inspection panel detailing:
- **ATM Identification:** ATM ID, Bank Operator, Operating District, Precise GPS Coordinates.
- **Assigned Probability:** Exact model probability for selected window.
- **Top 3 Explainability Reasons:** Plain-language feature attributions generated by tree SHAP decomposition.
- **Evidentiary Source Records:** Clickable links to historical transaction IDs and account numbers justifying the prediction.

### 3.3 Case-Level Evaluation Drawer
A built-in benchmark drawer displays live model performance on chronological holdout data:
- **Top-5 Hit Rate:** Percentage of test cases where the actual cash withdrawal occurred in the top-5 ranked ATMs.
- **Precision@5:** Proportion of top-5 ATMs experiencing actual withdrawals (alongside the theoretical maximum case ceiling).
- **Statistical Rigor:** All metrics display sample size $n$ and 95% bootstrap confidence intervals, preventing misleading claims on small sample slices.
